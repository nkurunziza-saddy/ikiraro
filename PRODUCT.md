# Product

## Register

brand

## Users

Developers evaluating and integrating the Ikiraro SDK. They arrive from the landing page, read SDK docs, and test the interactive demo before deciding to build on it. They are technical, skeptical of hype, and fast at scanning. Their primary job: assess whether this SDK is production-ready, well-documented, and worth the integration cost.

## Product Purpose

Sensa is the marketing and documentation surface for the Ikiraro SDK — a browser-native SDK that translates speech, text, and ASL into synchronized 3D sign animation. The SDK runs entirely on-device (vision path) or via Groq for STT/LLM. Sensa exists to convert developer skeptics into SDK adopters. Success means a developer leaves the site ready to `bun add @ikiraro/sdk`.

## Brand Personality

Quiet authority. Precise. Effortless.

The brand does not shout. It demonstrates. Every page earns trust through clarity and execution, not claims.

## Anti-references

- **Terminal / hacker dark**: No monospace-everywhere, no green-on-black, no dev-tool aesthetic. This SDK is for the browser and deserves a browser-native visual language.
- **SaaS cream / bubbly**: No pastel gradients, no friendly rounded blob UIs, no on-boarding cheerfulness.
- **Accessibility-badge heavy**: No leading with disability imagery, compliance theater, or medical-tool aesthetics. The product solves a real problem; the interface doesn't need to announce it.

## Design Principles

1. **Demonstrate, don't declare.** Show the SDK working rather than listing its features. Live previews and code blocks outweigh marketing copy.
2. **Earn every word.** If copy can be cut without losing meaning, cut it. Developers read fast and trust concision.
3. **Restraint as sophistication.** The SDK handles complexity invisibly; the interface should feel the same way. White space and small type signal confidence, not emptiness.
4. **System over decoration.** Consistency in spacing, type scale, and border treatment matters more than visual flourishes. Every element should feel like it belongs to the same quiet system.
5. **Speed reads before depth.** A developer scanning for 10 seconds should get the core proposition. A developer reading for 10 minutes should find complete answers without hunting.

## Accessibility & Inclusion

WCAG AA minimum. The product serves developers who may themselves be building for deaf/HoH users — the interface should model accessible defaults. Reduced-motion preference should be respected where animations are used.
